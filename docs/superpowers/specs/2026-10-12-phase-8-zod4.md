# Phase 8 — Zod 3 → 4

**Branch:** `chore/upgrade-phase-8-zod4` (per master plan), forked from `develop`.
**Risk:** medium. **Size:** small — the codebase has few Zod touch points, and all of them are server-side.

## Context

Phase 8 of `docs/superpowers/plans/2026-06-11-dependency-upgrade-master-plan.md` upgrades `zod` from `^3.25.76` to 4.x. The phase runs after Phase 5 (Next 16 / React 19), Phase 6 (Tailwind 4), Phase 7 (Prisma 7) and the `fix/event-timezone-prague` PR. This spec was written on 2026-10-12 against `develop` at `3894f9a`, which is the state after Phase 4. Those later PRs may move code, so the execution plan has the implementer re-grep every touch point before editing. The **mappings** below stay valid whatever the surrounding code looks like.

The interactive brainstorming step was skipped by request. All decisions were taken and recorded here.

### Duplicate Zod copies

Today the tree holds two copies: `zod@3.25.76`, hoisted (ours), and `zod@4.4.3`, nested under better-auth. After the bump, yarn 1 keeps a separate lock entry (`zod@^4.3.6` → 4.4.3) next to ours (`zod@^4.6.6` → 4.6.6) unless the lockfile is deduplicated. Mixed instances are not a correctness problem here:

- Zod 4's `instanceof` checks match on internal traits, not prototype identity.
- No schema crosses into Better Auth.

We dedupe anyway so the tree ships exactly one Zod. See D6.

## Zod usage inventory (at `3894f9a`)

`grep -rnE "zod|\bz\." src prisma e2e` matches 3 files. `prisma/` and `e2e/` have no Zod usage.

| File | Current (v3) | Zod 4 change |
|---|---|---|
| `src/env.js` | `DATABASE_URL: z.string().url()` | `z.url()`. Plain `z.url()` only checks `URL.canParse`, so `postgresql://…` still passes. Do **not** use `z.httpUrl()`. |
| `src/env.js` | `BETTER_AUTH_URL: z.preprocess(fn, z.string().url())` | `z.preprocess(fn, z.url())`. `preprocess` now returns a `ZodPipe`, which needs no code change. |
| `src/env.js` | `BOOTSTRAP_ADMIN_EMAIL: z.string().email()` / `.email().default('admin@cmdrozdi.cz')` | `z.email()` / `z.email().default('admin@cmdrozdi.cz')`. `.default()` now short-circuits on `undefined` and returns the default without parsing it, and the default must match the *output* type. The value is a valid string literal, so behaviour is the same. No `.prefault()` needed because there is no transform. |
| `src/env.js` | `NODE_ENV: z.enum([...]).default('development')`, `z.string()`, `z.string().optional()` | unchanged |
| `src/server/api/trpc.ts` | `error.cause instanceof ZodError ? error.cause.flatten() : null` | Keep the `instanceof ZodError` check: it works through Zod 4 traits, and the thrown class `ZodRealError` extends `Error`, so tRPC keeps it as `cause`. Replace the deprecated `.flatten()` with `z.flattenError(error.cause)`, which returns the same `{ formErrors, fieldErrors }` shape. **Never** test `instanceof ZodRealError`: its `Symbol.hasInstance` matches *any* `Error`. |
| `src/server/api/routers/event.ts` (`create`) | `id: z.string().cuid().optional()` | `z.cuid().optional()`. See the cuid note below. |
| same | `start` / `end: z.coerce.date().optional()` | `z.coerce.date<Date>().optional()`. Zod 4 makes every `z.coerce.*` **input** type `unknown`, which would turn `TCreateEvent['start']` (`RouterInput['event']['create']`, used by `useEventForm`) into `unknown` and silently drop client type safety. The generic restores the v3 input type `Date`. |
| same | `email: z.string().email().optional()` | `z.email().optional()`. The v4 email regex accepts the same practical set as v3 (no `%`, no leading or double dot). |
| same | `name`, `phone`, `description`, `location: z.string()…`, `isPrivate: z.boolean()` | unchanged |
| `event.ts` (`changeState`) | `id: z.string().cuid()`, `state: z.nativeEnum(EventState)` | `z.cuid()`, `z.enum(EventState)`. `EventState` is a **numeric** TS enum. Zod 4 `z.enum` filters out the reverse-mapping keys, so it accepts exactly `0..3`, as `nativeEnum` did. |
| `event.ts` (`deleteById`) | `id: z.string().cuid()` | `z.cuid()` |
| `src/server/api/routers/member.ts` | `z.nativeEnum(UserRole).refine(fn, { message: 'Lze přiřadit pouze roli Člen nebo Admin.' })` | `z.enum(UserRole).refine(fn, { error: 'Lze přiřadit pouze roli Člen nebo Admin.' })`. `UserRole` is a **string** enum. `refine` no longer wraps in `ZodEffects`. |
| `member.ts` (`create`) | `email: z.string().email()`, `name: z.string().min(1)` | `z.email()`; `name` unchanged |
| `member.ts` (other procedures) | `z.object({ userId: z.string() })`, `{ token: z.string(), newPassword: z.string() }` | unchanged |

**cuid note:** `z.cuid()` in v4 uses the regex `^[cC][0-9a-z]{6,}$`. v3 used `^c[^\s-]{8,}$` (case-insensitive). Prisma's `@default(cuid())` generates cuid v1 ids (`c` + lowercase alphanumerics), which pass. If Phase 7 switched any `@id @default(...)` to `cuid(2)`, use `z.cuid2()` for that model's ids instead, because cuid2 ids need not start with `c`.

## Decisions

- **D1 — Target `zod@^4.6.6`**, or the newest 4.x on `npm view zod version` at execution time. Keep the existing `import { z } from 'zod'` style, since the named export still exists in v4, so the diff stays minimal. Do not use `zod/mini` or `zod/v4` subpaths.
- **D2 — Zero deprecated Zod APIs after the phase.** v4 still accepts method-form formats, `nativeEnum`, `message` and `.flatten()`. We migrate them all anyway so a future Zod 5 is a no-op. Exit grep: see Testing.
- **D3 — Keep coercion: `z.coerce.date<Date>()`** rather than switching to `z.date()`. This keeps the accepted runtime inputs and the client input type exactly as in v3.
- **D4 — No validation tightening.** Use `z.url()`, not `z.httpUrl()`, for both URLs. Keep email and id rules equivalent to v3. Behaviour changes are out of scope.
- **D5 — Keep the tRPC `zodError` response shape** `{ formErrors, fieldErrors }` through `z.flattenError`, not `z.treeifyError`. No client reads it today, but it is part of the API contract and the new e2e spec pins it.
- **D6 — One Zod copy.** After `yarn add`, collapse the nested `zod@^4.3.6` lock entry into ours, so `yarn why zod` reports a single hoisted `zod@4.x` that also satisfies better-auth's range. Re-check if Phase 5 or 7 bumped better-auth.
- **D7 — No `@hookform/resolvers`.** Client forms keep react-hook-form `rules`. Moving forms onto shared Zod schemas would be a feature change, out of scope. If a later phase added `@hookform/resolvers`, it must be `>=5.1` (the first line with Zod 4 support), and its `zodResolver` call sites join this phase's inventory.
- **D8 — e2e coverage.** Add a new `e2e/specs/input-validation.spec.ts` that hits the tRPC HTTP endpoint directly and asserts:
  - `zodError` for an invalid email;
  - the `z.enum(EventState)` accept/reject boundary;
  - the Czech custom `refine` message.

  Also add one UI test to `event-crud.spec.ts`: a start time in the past renders `Začátek nesmí být v minulosti` and keeps `Potvrdit` disabled. That covers the "form validation errors still render" exit criterion. Write the tests **before** the bump. They describe v3 behaviour that v4 must keep.
- **D9 — Env fail-fast is checked manually, not automated.** CI builds with `SKIP_ENV_VALIDATION=1`, so it cannot cover this. The documented commands (Testing, items 4 and 5) are run once, and their output goes in the PR body.
- **D10 — Lint command.** Use whatever `lint` script `package.json` has at execution time (`next lint` today; `eslint .` after Phase 5). Always prefix it with `SKIP_ENV_VALIDATION=1`, as CI does.

## Testing & exit criteria

1. Verification gate, in order, every command with Node 22 (`export PATH="$HOME/.nvm/versions/node/v22.14.0/bin:$PATH" && …`) and native Postgres on `localhost:5432`:
   1. `yarn install --frozen-lockfile`
   2. `npx prisma generate`
   3. `SKIP_ENV_VALIDATION=1 yarn lint`
   4. `SKIP_ENV_VALIDATION=1 yarn typecheck`
   5. `SKIP_ENV_VALIDATION=1 yarn build`
   6. `yarn e2e`, run once at the end only

   All must pass clean.
2. `yarn why zod` shows a single `zod@4.x` and no `3.x`.
3. Deprecated-API grep over `src prisma e2e` (see plan Task 3) returns nothing.
4. **Env fail-fast, missing var, through the build:** `env -u SKIP_ENV_VALIDATION DATABASE_URL= yarn build` must exit non-zero, printing `❌ Invalid environment variables:` with a `DATABASE_URL` issue. The empty value counts as missing because `emptyStringAsUndefined: true`, and `@next/env` does not override an env key that is already set (even when empty) with the `.env` value.
5. **Env fail-fast, isolated:** `env -i PATH="$PATH" HOME="$HOME" NODE_ENV=production node --input-type=module -e "await import('./src/env.js')"` must throw `Invalid environment variables`. The listed issues must include `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` and `BOOTSTRAP_ADMIN_EMAIL`.
6. **Env positive control:** `node --env-file=.env --input-type=module -e "await import('./src/env.js'); console.log('env ok')"` prints `env ok`.
7. **Form validation errors render:** the new e2e UI test passes. A manual Playwright-MCP smoke on `yarn dev` repeats it: open the Rezervovat form, pick today at 00:00, see the error, see `Potvrdit` disabled. Then create a valid event and a member successfully.

## Non-goals

- Changing any validation rule, error copy, or the English Zod default messages. Example: member-create errors still toast the raw tRPC message, as today.
- Adopting Zod on the client or `@hookform/resolvers`.
- Bumping tRPC, better-auth, `@t3-oss/env-nextjs`, or anything else not needed for Zod 4.
- Zod 4 feature adoption (`z.toJSONSchema`, metadata registries, `zod/mini`).
